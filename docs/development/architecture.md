# アーキテクチャ

hikidashi の設計原則と仕組みの構成。何を解くか・語彙は [`../business/concept.md`](../business/concept.md) が持つ。

## 設計原則

### 1. クライアントのリポジトリに痕跡を残さない

- 受託案件のリポジトリにある `CLAUDE.md` や `.gitignore` には一切手を入れない
- 設定はすべてユーザーレベルの `~/.claude/settings.json` に置く
- データはすべてリポジトリ外の `~/.hikidashi/` に置く（下記「データの置き場」）

### 2. 書き手ごとに形式を分ける

| データ | 書き手 | 形式 | 理由 |
| --- | --- | --- | --- |
| 備忘録 | 人間 | Markdown | エディタでそのまま編集でき、エージェントにも読ませやすい |
| セッション状態 | hook | 1 セッション 1 ファイルの JSON | 書き手が分かれるため同時書き込みで競合しない。`jq` / fzf で扱いやすい |
| 履歴・集計（将来） | hook | SQLite（`~/.hikidashi/history.db`） | 放置時間や作業履歴の集計が必要になった段階で追加 |

- JSON の書き込みは一時ファイル → rename でアトミックに行う
- SQLite を足した後も、JSON は「現在値のキャッシュ」として残せる

### 3. 状態は決定論、次アクションは抽出

- **状態**（走行中 / 入力待ち / アイドル / 終了）は hook のイベントから確実に判定する。LLM は使わない
- **次アクション**（いま何をしていて、次に何をすべきか）は会話ログから要約して抽出する

## 仕組みの構成

### hooks（中核）

| hook | 役割 |
| --- | --- |
| `SessionStart` | その案件の備忘録を標準出力し、コンテキストに注入する（CLAUDE.md の代わり） |
| `UserPromptSubmit` | 人間が応答し、走行中に戻ったことを記録する |
| `Notification` | 入力待ちになったことを記録する |
| `Stop` | ターン終了を記録し、次アクションの抽出をバックグラウンドで起動する |
| `SessionEnd` | セッション終了を記録する |

- 記録する項目: `session_id`、作業ディレクトリ、`$TMUX_PANE`、状態、時刻
- worktree を使う場合は `git rev-parse --git-common-dir` からメイン worktree を割り出し、1 案件 1 引き出しに寄せる

### 次アクションの抽出

- `Stop` 時に `transcript_path` の末尾をヘッドレス実行の軽量モデル（例: `claude -p --model haiku`）に渡す
- 出力は固定スキーマ: 要約 / 人間の次アクション / Claude の次アクション / ブロッカー
- hook を待たせないようバックグラウンドで実行し、連続したイベントは間引く

### データの置き場

```
~/.hikidashi/
└── drawers/<slug>/
    ├── drawer.json                  # リポジトリのパス等
    ├── notes.md                     # 備忘録
    └── sessions/<session_id>.json   # セッション状態
```

- リポジトリ内（`<repo>/.hikidashi/` を `.git/info/exclude` で除外）は採らない。`.git` も案件リポジトリの一部であり、原則 1 に反するため
- `<slug>` はリポジトリのパスから作る（例: `github.com-org-a-api`）。リポジトリ名だけでは別 org の同名リポジトリが衝突するため
- 備忘録がリポジトリの横に無い分は、`$EDITOR` で `notes.md` を開くコマンドで補う
- リポジトリを移動すると `drawer.json` のパスが古くなる。頻度が低いため、移動時は登録し直す

### 引き出しの登録

- hook が初めて発火したときに `drawers/<slug>/` を作る。これが登録であり、別途の一覧ファイルは持たない
- 引き出しの一覧は `drawers/` 配下のディレクトリの列挙で得る。ディレクトリ作成は冪等なので、同時発火でも競合・重複しない
- tmux のセッション名はリポジトリ名に揃える

### UI

- tmux の `display-popup` で fzf ベースの一覧を開く
- 引き出し（案件）→ セッションの順に、状態と次アクションを並べる
- Enter で `tmux switch-client` し、該当 pane に移動する
- ステータスバーには入力待ちの件数だけを表示する
